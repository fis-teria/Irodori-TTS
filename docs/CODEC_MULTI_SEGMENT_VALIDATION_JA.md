## 2. 区間の選定（推論前）

前回の15–35秒と重ならない **55–75 / 100–120 / 145–165秒** を事前に指定した。「本質的に無音」は、モノラルRMSが −50dBFS 未満、または −50dBFS を超える25msフレームが25%未満、と事前に定義した。無音の場合は、5秒刻みで後方（その後先頭に戻る）を探し、重ならず無音でない最初の区間に置き換える規則にした。

| 区間 | サンプル境界（44.1kHz） | RMS | −50dBFS超のフレーム | 判定 |

| 55–75秒 | 2,425,500 – 3,307,500 | −23.8dBFS | 100% | 採用 |
| 100–120秒 | 4,410,000 – 5,292,000 | −23.3dBFS | 85% | 採用 |
| 145–165秒 | 6,394,500 – 7,276,500 | −20.1dBFS | 98% | 採用 |

## 3. 測定結果（事実）

旧経路 = 区間をそのまま（ステレオ44.1kHz）ラッパーへ渡す。候補 = モノラル化・48kHz化してから −16 LUFS に整え、復元後に同じゲインで割り戻す。対照 = コーデックなしで 48→44.1→48kHz に再サンプルしたもの。いずれも同じ48kHzモノラル原音と比較した。

| | 55–75秒 | 100–120秒 | 145–165秒 | 参考：前回15–35秒 |
|---|---:|---:|---:|---:|
| 候補の入力ゲイン | +7.32dB | +6.84dB | +3.49dB | +12.66dB |
| 候補の入力ピーク（ゲイン後） | 0.563 | 0.853 | 0.789 | 約0.87 |
| 発声区間LSD 旧経路 / 候補 | 8.88 / 8.89 | 8.95 / 8.95 | 9.63 / 9.65 | 9.28 / 9.12 |
| 発声区間LSD コーデックなし対照 | 0.19 | 0.16 | 0.19 | 0.11 |
| 倍音コントラスト差 300–3kHz 旧 / 候補 | −7.39 / −7.48 | −4.18 / −4.30 | −7.81 / −7.82 | −3.02 / −3.25 |
| 倍音コントラスト差 8–16kHz 旧 / 候補 | −2.60 / −2.73 | −3.64 / −3.40 | −2.08 / −2.28 | −4.19 / −4.55 |
| 帯域パワー差 6–10kHz 旧 / 候補 | −2.74 / −3.45 | −3.20 / −3.32 | −3.08 / −3.39 | — |
| 帯域パワー差 10–16kHz 旧 / 候補 | −3.04 / −3.14 | −3.61 / −3.62 | −3.18 / −3.27 | — |

- 全条件で出力は有限値、クリップ0、相互相関の遅延0サンプル。復号は入力と同じ長さ（960,000サンプル）で、末尾の切り落とし・ゼロ埋めはどちらも0。候補の復号ピーク（割り戻し前）は最大0.863で、1.0未満。
- 候補と旧経路のLSD差は +0.016 / +0.005 / +0.022dB（候補がわずかに大きい）。**どちらが良いとも言えない大きさで、客観的な改善とは呼ばない。** 前回の区間はゲイン +12.7dB で差が出たが、今回は入力が大きくゲインも小さい。入力の大きさが差の小ささの原因である可能性はあるが、区間ごとに歌の内容も違うため、これは仮説にとどまる（6章）。
- コーデックなし対照のLSDは0.2dB以下。約9dBのLSDと高域・倍音コントラストの低下は、再サンプルではなくコーデックによる変化である。ただし、これが聴感上どれだけ問題かはこの指標では決められない（前回の区間も同程度の値で「ほぼ遜色ない」と評価された）。
- 16kHz以上：原音の発声区間の16–22kHz帯域は −84〜−91dBFS とごく小さい（測定値のみ。理由は推定しない）。復号との差は −6〜+5dB あるが、絶対レベルが非常に低く、解釈しない。

### 静音区間（DC/AC 分離）

原音で決めた区間（完全な0が続く最長区間、なければ −60dBFS 未満の10msフレームが続く最長区間。両端50msを除き200ms以上）だけで比較した。

| 区間 | 静音区間 | 原音 AC RMS | 旧経路 AC RMS（DC比率） | 候補 AC RMS（DC比率） |
|---|---|---:|---:|---:|
| 55–75秒 | 該当なし（指標なし） | — | — | — |
| 100–120秒 | 17.62–18.08秒（0.46秒） | −68.29dBFS | −70.83（15.5%） | −69.90（2.8%） |
| 145–165秒 | 0.12–0.32秒（0.20秒） | −63.90dBFS | −65.60（4.6%） | −65.42（1.9%） |

原音にもともと −64〜−68dBFS の小さな音があり、デジタル無音ではない。どちらの経路もこの区間のAC RMSは原音より約1.5〜2.5dB小さく、**選んだ区間では総AC量の増加はなかった。** ただし、原音の成分が弱まる一方で新しいノイズが加わることもありうるため、エネルギーの比較だけでは「ノイズが加わっていない」とは言えない。直流成分は前回の話し声ほど支配的ではない。区間が短く、ノイズの聴感評価の代わりにはならない。

### F0（音高の追跡、品質の点数ではない）

pYIN（16kHz、10ms、65–1100Hz、時間合わせなし）。原音の有声フレームを分母とし、出力が無声ならその分は失敗として数える。

| 区間 | ±50セント以内（原音の有声フレーム中）旧 / 候補 | オクターブ誤差 旧 / 候補 | 出力も有声 旧 / 候補 |
|---|---:|---:|---:|
| 55–75秒 | 97.6% / 97.0% | 0.0% / 0.9% | 98.8% / 98.8% |
| 100–120秒 | 94.5% / 94.4% | 0.0% / 0.0% | 99.1% / 99.3% |
| 145–165秒 | 91.7% / 91.3% | 4.3% / 4.3% | 97.6% / 97.4% |

以下は推定器が付けた印であり、聴こえる音高のずれとは確認していない。F0の結果を一律に合格とはしない。

- 55–75秒の候補だけのオクターブ判定（16フレーム、区間内17.65–17.81秒 = 曲の72.65–72.81秒）。原音側の推定値が約1030Hzで探索上限1100Hzに近く、出力はその半分と判定された。原音側の推定誤りの可能性もあり、どちらが正しいかは決められない。
- 145–165秒では、旧経路・候補の **同じフレーム**（74フレーム、区間内10.00–10.74秒 = 曲の155.00–155.74秒）で、出力が原音（約517Hz）の2倍と判定された。この区間は ±50セント以内も91.7% / 91.3%と3区間で最も低い。両経路に共通するので、レベル条件の違いでは説明できない。コーデックによる変化か推定器の不安定さかは未確定で、試聴コメントと合わせて見る必要がある。

## 6. 分かったこと・分からないこと

**事実**：3つの別区間で、モデルカード条件の往復は数値的に安定していた（有限値、クリップなし、遅延なし、長さ一致）。客観指標は前回の区間と同じ程度。旧経路との差はこれらの区間ではごく小さい。重み・入力・前回のパックは変化していない。

**仮説**：
- −16 LUFS 条件の効果は入力が小さいときに大きく、今回のように大きな入力では旧経路とほぼ同じになる。今回のゲインの大きさと指標の差の小ささは整合するが、4区間だけでは確かめられない。
- 約9dBのLSDと倍音コントラストの低下は、すべての区間で共通するコーデックの性質と考えられる。前回の評価から聴感上は許容できる可能性があるが、区間ごとの試聴なしには言えない。

**未確定**：
- 新しい3区間の聴感（ノイズ感、ざらつき、明るさ、子音）。
- 静音区間で、新しいノイズが加わっているかどうか（総AC量は増えていないが、それだけでは判断できない）。
- 曲の72.65–72.81秒と155.00–155.74秒のF0判定が、聴こえる音高の変化なのか推定器の誤りなのか。
- 他の曲・他の歌手・より高い音域・息や強い子音の多い歌唱での挙動。

## 7. 本体での歌唱対応に進む判断

### コーデックの確認が意味すること

TTSが出力するのは32次元・25フレーム/秒のコーデック潜在（今回の20秒で500フレーム）。往復が良好なら、**「潜在が歌声を表現できない」というリスクが下がる。** それ以上のことは示さない。今回の確認は、正しい潜在が与えられたときの再構成の上限であり、モデルがその潜在を予測できること、声変換で目標の声に似ること、自然さが保たれることは何も示していない。

### ローカルのコードから見た制約

- `irodori_tts/model.py:1851`（`encode_conditions`）と `:2113`（`forward`）の条件入力は、テキストID、参照音声の潜在（話者）、キャプション、全体の長さ情報。**フレーム単位の音高・有声/無声・内容（元の歌の発音）を入れる経路はない。**
- 学習設定の **既定値** は `max_latent_steps: 750`（`irodori_tts/config.py:195`、25フレーム/秒で30秒相当）。これは既定値であり、チェックポイントの上限や、学習がメモリに収まることを示すものではない。
- LoRA設定（`configs/train_500m_v3_lora.yaml:70–75`）は `diffusion_attn` が対象で、新しい入力経路は追加しない。**LoRAだけでは、元の歌のタイミングや音高に合わせる仕組みは作れない。**

ユーザーの当初の目的は、既存の歌（元の歌手）を目標の声に変換すること（RVCのような使い方）であり、歌詞と楽譜からの歌声合成ではない。本体での試作はこの方向に合わせる。具体的には、元の歌から得たフレーム単位の内容と F0・有声/無声を25fpsに合わせて入力し、目標の声は参照音声で与え、コーデックは現在のものを使う。歌詞の自動書き起こしは前提にしない。

### 判断

| 対象 | 判断 | 条件・理由 |
|---|---|---|
| コーデック（モデルカード条件）を歌の表現に使い続ける | **条件付きで可** | 数値面は4区間で安定。今回の3区間でユーザーがコーデック由来の問題を指摘しないことが条件。指摘があれば、その区間と現象を特定してから進む |
| 小規模な本体試作（既存のモデルに、フレーム単位の音高・内容を入れる小さな経路を追加して試す） | **条件付きで可** | 上の条件に加え、1曲・短区間の範囲で事前に成功条件を決める。比較対象は「コーデック往復の上限」と既存のSeed-VC結果。評価は試聴を主にし、F0やLSDだけで合否を決めない |
| 大規模な学習（歌唱データを集めた全体の追加学習、コーデックの再学習・高次元化） | **現時点では不可** | 小規模試作で、条件付けの方式が音高・タイミングを保てるかがまだ示されていない。コーデックの変更が必要という根拠もない |

小規模試作で確認すべきことは、①元の歌の音高とタイミングを保てるか、②目標の声への似方、③自然さ・ノイズ感。いずれも聴いて判断する。今回の結果はこのうちどれも示していない。
