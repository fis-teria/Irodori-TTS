## 1. コード監査で分かったこと（観察）

| 項目 | 実装の内容 |
|---|---|
| モノラル化・リサンプル | ラッパーがチャンネル平均を取り、torchaudio で 44.1→48 kHz に変換する |
| レベル | モデルカードの推奨は −16 LUFS 正規化＋`ensure_max`。旧ラウンドトリップは `normalize_db=None` で、約 −29 dBFS のまま通していた（ピーク > 1 のときだけ縮小） |
| 事後分布 | ラッパーは encoder→`_pad`(reflect)→`in_proj` の平均を使い、サンプリングしない。`DACVAE.encode` 本体は `randn` でサンプリングする |
| デコーダの乱数 | 音声経路に乱数はない。透かしの `random_message` は固定化されたうえ、透かし枝ごと迂回している。迂回方法（`alpha=0` ＋ `encoder_block.forward_no_conv`）はモデルカードと同じ |
| 精度・長さ | FP32（cuDNN TF32 は既定で有効）。出力長はフレーム数×1920 で、入力より長くなる場合がある（旧 heldout 出力は末尾 1349 サンプル長い） |

## 3. レベル条件付けのアブレーション（観察）

入力を一定量持ち上げてから符号化し、デコード後に同じゲインを正確に戻した。−16 LUFS 版の実ゲインは歌 +12.7 dB（ピーク 0.87、上限は audiotools の 1.0）、話 +8.1 dB。+12 dB 版はピーク 0.95 で頭打ちになり、話では +9.8 dB だった。

- コントラストは、各フレーム・各帯域のビン dB の 90 パーセンタイルと 25 パーセンタイルの差。原音とデコード音それぞれで独立に計算しているので、原音の谷だけを選んで比べるときの平均回帰バイアスがない。値が下がるのは、倍音の間がエネルギーで埋まるか、倍音のピークが平らになったことを意味する。I/O 対照では差は 0.0〜−0.1 dB だった。
- 入出力の波形誤差（歌 −9.2 dB）には位相誤差や歪みが含まれるので、ノイズ量そのものとは扱わない。
- 合成プローブ（領域外の対照）: デジタル無音を入れると、出力は約 −77 dBFS の一定値になった。これは DC オフセット 1.4e−4 にほぼ相当する。トーン間の無音部も同じ −77 dBFS で、入力を +10 dB 持ち上げて戻すと −87 dBFS に下がった。入力レベルに依存しない、固定の小さな下限がある。
- F0（pYIN、フレーム位置合わせのみ）: baseline も −16 復元も、相関 0.996〜0.997、±50 セント以内 95% で、ピッチは保たれている。

## 4. 解釈（観察と仮説を分けて記す）

- **観察**: リサンプル・I/O・精度・乱数・透かし迂回・ラッパー実装は、いずれも差の原因から外れた。
- **観察**: 「静かな入力（−29 dBFS）を正規化なしで通した」ことの影響は、話し声のポーズに出る固定下限（高域・DC）に限られた。モデルカードのレベルで符号化してゲインを戻すと、この下限は発声比で 8〜10 dB 下がる。ただし絶対レベル（中央値）は −76 → −84 dBFS とごく小さい。これは合成無音で測った固定下限（約 −77 dBFS）と同程度の水準で、22 kHz 以上の可聴域外の生成成分も一緒に下がる。
- **観察**: 歌では、レベルを変えてもほぼ変わらない劣化が残った。倍音コントラストの低下（300–3k で −3 dB、8–16k で −4 dB）と、3 kHz 以上の減衰（−2〜−5 dB）である。同じコーデックでも話し声ではコントラスト低下は −0.4〜−0.7 dB にとどまる。
- **仮説（未検証）**: ユーザーが感じた「ノイズ感」は、歌の倍音の間が埋まること（息っぽさ・ざらつき）と、高域の質感の変化によるもの。これは 32 次元潜在表現かデコーダの、歌声に対する限界と考えられる。前処理の問題でも、確率的なノイズでもない。どちらの限界かは、このチェックポイントだけでは切り分けられない。128 次元版などの別コーデックはキャッシュになく、大きなダウンロードを避けるため比較していない。仮に比べても 32 次元チェックポイントとは互換性がないので、製品の置き換え候補にはならない。
- 「改善」とは言わない: −16 LUFS 復元は、モデルカードと条件を揃えた**候補**にすぎない。歌の数値はほとんど変わらず、16–22k はむしろ 1.4 dB 下がる。音が静かになったことや F0 指標を、品質向上の根拠にはしない。

## 7. 次の推奨

1. 試聴（任意）で、歌の 2 と 3 に差がないか、話のポーズ部に差があるかを確認する。
2. 今後のコーデックゲートは `--input-level model-card` で取る。モデルカードと条件が揃い、話し声ポーズの床も下がる。
3. 歌のネイティブ対応を判断するには、倍音コントラストと高域を見るゲートが必要。これはコーデック表現の問題なので、前処理やポストフィルタでは直らない。改善には、歌を含むデータでのコーデック（デコーダ）微調整か、高次元潜在のコーデックが必要と見込む（学習を伴うので別タスク）。デノイズや EQ で隠す処理を主な対策にはしない。
