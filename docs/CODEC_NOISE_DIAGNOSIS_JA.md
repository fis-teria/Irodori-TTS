# DACVAE コーデック往復のノイズ切り分けと改善検証

2026-11-01。**今回の歌20秒では、入力をモデル推奨の −16 LUFS に整え、復元後に元のゲインへ戻す候補を、ユーザーが「元の歌唱とほぼ遜色ないですね」と評価した。** 旧経路で感じたノイズに対し、レベル条件の修正は実用的な改善候補になった。ただし、記名式試聴・1人・1区間の定性的評価であり、無劣化や全曲への一般化は示していない。

Opus がコーデック単体の対照実験と実装を担当し、Codex がコード・測定単位・結論をレビューした。TTS生成、Seed-VC変換、追加学習は今回実行していない。

## 2. どの経路に問題があったか

[モデルカード](https://huggingface.co/Aratako/Semantic-DACVAE-Japanese-32dim)の例は、−16 LUFS正規化とピーク制限後、事後分布の平均を使って符号化する。旧 `dacvae_roundtrip.py` は比較用に `normalize_db=None` を明示しており、今回の小さい入力をそのまま通していた。**診断用往復の入力条件に改善余地があった。** Irodori本体のコーデック既定値は既に −16 であり、本体全体に同じ欠落があるという意味ではない。

| 対照 | 観測と解釈 |
|---|---|
| 旧出力の再現 | 共通サンプルの最大差0。話し声の旧出力は末尾パディング分だけ長いため、共通範囲で比較 |
| モノラル化・リサンプル | ラッパーと同じチャンネル平均・torchaudioの44.1→48kHzを使った |
| ラッパーとモデルカードの直接経路 | 同じ条件の潜在・出力とも最大差0。ラッパー固有の差は見つからなかった |
| 同じ入力を繰り返す | 最大差0。旧経路は事後平均を用い、音声を確率的にサンプリングしない |
| float WAVの書き戻し | 最大差0 |
| コーデックなしの48→44.1→48kHz | 歌の波形誤差 −64.8dB、発声区間LSD 0.11dB。コーデックによる差より小さい |
| cuDNN TF32を無効化 | 差のRMSは約 −92dBFS。今回の主因とは考えにくい。変更したフラグは復元した |
| 事後サンプリング診断（seed 0） | 平均経路との差は歌約 −49dBFS、話約 −45dBFS。旧経路はこのサンプリングを使っていない |
| 遅延・クリップ | 実音声の主要4条件では遅延0サンプル、クリップ0 |
| 透かし | `alpha=0` と `encoder_block.forward_no_conv` の組み合わせはモデルカードと一致。別のSilentCipher後処理はこの往復では呼んでいない |

これらは今回試した条件での確認であり、あらゆる入力・精度・透かし設定の影響を排除するものではない。

## 3. レベル条件を変えた結果

同じ48kHzモノラル音声を入力とし、符号化前に一定ゲインを加え、復元後に同じゲインで割った。単に再生音量を小さくする処理ではない。モデル推奨条件の実ゲインは歌 +12.66268dB（入力ピーク約0.87）、話 +8.05571dB。手動 +12dB条件はピーク0.95制限により話では +9.76231dBだった。

| 歌20秒 | 旧経路 | +6dB | +12dB | −16 LUFS・逆ゲイン |
|---|---:|---:|---:|---:|
| 当てはめゲイン（dB） | −1.05 | −0.90 | −0.59 | −0.55 |
| 発声区間LSD（dB） | 9.28 | 9.18 | 9.12 | 9.12 |
| 倍音コントラスト差300–3kHz（dB） | −3.02 | −3.15 | −3.24 | −3.25 |
| 倍音コントラスト差8–16kHz（dB） | −4.19 | −4.21 | −4.51 | −4.55 |
| 帯域パワー差3–6kHz（dB） | −1.83 | −2.13 | −2.45 | −2.48 |
| 静音区間の発声比（dB、原音 −41.28） | −42.22 | −42.43 | −42.76 | −42.78 |

LSDの改善は小さく、高域と倍音構造の差も残る。コントラストは各フレームの帯域内ビンレベルの90・25パーセンタイル差であり、両音声で独立に計算した。低下は倍音間へのエネルギー増加やピークの平坦化と整合するが、どちらの原因か、聴感上どれだけ問題かはこの指標だけでは決められない。波形誤差やF0も品質・ノイズの点数ではない。

F0は旧経路・改善候補とも共通有声区間の約95%が±50セント以内、相関0.996〜0.997。音高保持の参考にはなるが、自然さの合格判定には使わない。

## 4. 無音部分はDCとACを分ける必要があった

レビューで、初回の帯域パワーの単位と、DC/Nyquistを含む片側FFTの重みを修正した。旧JSONの帯域絶対値は使わず、保存済み音声からレビュー版を再計算した。フレーム・帯域パワーの数値下限は −100dBFSなので、それ以下の差はこの表現では比較できない。

話し声の原音が厳密に0である最長区間から、両端50msを除いた **15.85–16.84秒** を独立に解析した。以下のAC値はFFTの下限を使わず、時間波形から直接計算している。

| 同じ無音区間 | 旧経路 | −16 LUFS・逆ゲイン |
|---|---:|---:|
| 総RMS（dBFS） | −77.99 | −86.04 |
| 平均値を除いたAC RMS（dBFS） | −103.52 | −111.25 |
| 総エネルギー中のDC比率 | 99.72% | 99.70% |

総RMS低下の大半はほぼ一定の直流オフセットに関係する。**約8dB下がった値を、そのまま可聴ヒスノイズの改善量とは呼べない。** 合成デジタル無音・トーン間の無音にも小さい固定下限が見られ、ゲインを上げて戻すと下がったが、歌のざらつきの直接原因とは立証できていない。無音入力の出力は厳密な0ではなく、端部過渡もある。

## 5. ユーザーの試聴結果

提示済み `listening_pack/` は48kHz PCM24。歌・話それぞれのグループ内で、減衰のみを使って発声区間RMSを一致させた（歌 −28.70dB、話 −24.03dB、ピーク −1dBFS以下）。この音声と記録は保持した。

- 歌: `singing20s_1_original.wav` / `singing20s_2_baseline_old_path.wav` / `singing20s_3_candidate_lufs_m16_restored.wav`
- 話: `heldout_speech_1_original.wav` / `heldout_speech_2_baseline_old_path.wav` / `heldout_speech_3_candidate_lufs_m16_restored.wav`

旧経路に対するノイズ感・ざらつき・明るさ・子音の比較を尋ねたところ、ユーザーは **「元の歌唱とほぼ遜色ないですね」** と回答した。候補の実用的な聴感は良好と受け取れる。一方、個別項目の数値、全条件の再採点、話し声の評価はもらっていない。1人・1歌唱区間・非ブラインドのため、統計的優位や全曲での改善は主張しない。

初回分析の「歌ではほとんど違わないはず」という予想は、結論には採用しない。**客観指標の小さい変化だけから、聴感上の改善を否定することもできない。** 同時に、この回答から無劣化を断定することもできない。

## 6. 実装と検証

- `scripts/codec_noise_diagnosis.py`: コーデック対照実験・試聴パック・F0。新しい結果ルートに保存し、既存パックや入力を上書きしない。
- `singing_vc/codec_diag.py`: ゲイン条件、逆ゲイン、遅延、帯域、コントラスト、DC/AC分離。極小入力のゲイン計算、非有限ゲインの拒否、片側FFTの単位もレビューで修正した。
- `scripts/dacvae_roundtrip.py`: **`--input-level model-card`** を追加。既定のrawは旧比較の再現用に保持。デジタル無音は正規化を省略し、不定なゲインを避ける。入力・出力・JSONの同一ファイル指定（ハードリンク含む）はモデル読込前に拒否する。
- `irodori_tts/codec.py` とTTSの既定動作は変更していない。

検証は数値・保存先保護16件と既存歌唱43件の計59件が合格。レビュー後のGPU実行でも、実歌20秒の出力は診断時候補と最大差0、デジタル無音1秒もNaN/Infなし。無音を無音のまま返す機能ではない。

PowerShellでの再現例（プロジェクトルートから。出力には新しいパスを指定する）:

```powershell
.venv\Scripts\python.exe scripts\dacvae_roundtrip.py --input song.wav --output outputs\singing\new_check\song_restored.wav --json outputs\singing\new_check\run.json --input-level model-card
.venv\Scripts\python.exe scripts\codec_noise_diagnosis.py run --source song.wav --heldout speech.wav
.venv\Scripts\python.exe scripts\codec_noise_diagnosis.py pack --root <新しい結果ルート> --candidate lufs_m16_restored
.venv\Scripts\python.exe -m unittest discover -s tests -p test_codec_diag.py
```

## 7. 歌唱対応へ進む判断

今回の結果では、**コーデックのノイズだけを理由にIrodori本体の歌唱検討を止める必要性は下がった。** 今後の往復確認はモデル推奨条件で行うのが妥当。ただし、改善したのは診断用の符号化・復元経路であり、TTSが歌詞・音高・長さを学べることや、Seed-VCで似方・自然さが改善したことはまだ示していない。

次は、同じ入力条件で別の歌唱区間も確認し、以前の声変換の自然さ低下はコーデック評価と分けて判断する。（同じ曲の別3区間での確認は [CODEC_MULTI_SEGMENT_VALIDATION_JA.md](CODEC_MULTI_SEGMENT_VALIDATION_JA.md) を参照。）本体の歌唱学習に着手する前には、音高・長さをどう条件付けるかを小規模に設計する。

残るスペクトル差がエンコーダ・潜在次元・デコーダのどこに由来するかは未確定。コーデック微調整や高次元版が必要とはまだ結論しない。別次元のコーデックは既存32次元TTSとの単純差し替えはできず、今回は比較していない。
